# Отчет о тестировании класса BankAccount

## Вывод о проведенном тестировании

В процессе выполнения практической работы было разработано и выполнено 5 модульных тестов для проверки методов Debit и Credit класса BankAccount. Тесты охватывают как позитивные сценарии, так и исключительные ситуации, что позволяет оценить корректность реализации и обработку граничных значений.

## Результаты выполнения тестов

| № | Тестовый метод | Результат | Причина успеха / неудачи |
|---|----------------|-----------|--------------------------|
| 1 | Debit_WithValidAmount_UpdatesBalance | Первый запуск: ❌ НЕ ПРОЙДЕН<br>После исправления: ✅ ПРОЙДЕН | Неудача: В исходном коде метода Debit использовался оператор += вместо -=, что приводило к увеличению баланса при списании, а не к уменьшению.<br>Успех: После замены += на -= тест подтвердил корректное уменьшение баланса. |
| 2 | Debit_WhenAmountIsLessThanZero_ShouldThrowArgumentOutOfRange | ✅ ПРОЙДЕН | Метод правильно определяет отрицательную сумму списания и выбрасывает исключение ArgumentOutOfRangeException. После рефакторинга тест также проверяет текст сообщения исключения, что повышает надёжность. |
| 3 | Debit_WhenAmountIsMoreThanBalance_ShouldThrowArgumentOutOfRange | ✅ ПРОЙДЕН | При превышении суммы списания над текущим балансом метод выбрасывает ожидаемое исключение. Проверка сообщения исключения добавлена для большей информативности. |
| 4 | Credit_WithValidAmount_IncreasesBalance | ✅ ПРОЙДЕН | Метод Credit изначально реализован верно: сумма зачисления правильно прибавляется к балансу. |
| 5 | Credit_WhenAmountIsLessThanZero_ShouldThrowArgumentOutOfRange | ✅ ПРОЙДЕН | Отрицательная сумма пополнения корректно вызывает исключение ArgumentOutOfRangeException. |

## Общий вывод

Проведённое тестирование позволило:

- выявить и устранить критическую логическую ошибку в методе Debit (неверный арифметический оператор);
- подтвердить корректную обработку исключительных ситуаций (отрицательные суммы, превышение баланса) в обоих методах;
- убедиться в правильной работе позитивных сценариев для Credit.

После исправления ошибки все 5 тестов завершаются успешно, что даёт основание считать реализацию класса BankAccount соответствующей требованиям. Использование подхода «белого ящика» и написание тестов до рефакторинга позволило быстро локализовать дефект и повысить общее качество кода. Документирование кода XML-комментариями дополнительно улучшило читаемость и поддержку проекта.
